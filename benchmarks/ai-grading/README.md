# 国語 AI採点ベンチマーク

目的: 早稲田渋谷シンガポール校の実際の国語過去問・公式模範解答を基準に、Workers AI の「問題を解く能力」と「答案を採点する能力」を分けて検証する。

## 安全方針

- 本番アプリの問題ID・学習履歴・公開データは変更しない。
- この `benchmarks/ai-grading/` 配下だけで検証する。
- Solver テストでは公式模範解答をモデルに見せない。
- Grader テストでは、後段で公式模範解答と人間確認済み rubric をモデルに見せる。
- プロンプト改善に使う問題と、最終テスト問題は分離する。
- 過去問本文をこの公開リポジトリへ長文複製しない。実行時に公式PDFをCloudflare Markdown Conversionでテキスト化する。

## 2024年度 seed

### 2024-1-6
- 形式: 自由記述
- 配点: 10点
- 字数: 40字以内
- 用途: AI自由記述能力の主テスト

### 2024-2-6
- 形式: 短答記述2欄
- 配点: 甲5点 + 乙5点
- 字数: 各10字以内
- 用途: 心情変化・短答の意味判定テスト

公式資料URL・短い公式模範解答・rubric draft は `2024/questions.json` に保存する。Solver実行時は `2024/solver-cases.json` の位置情報だけを使い、公式問題PDFから本文全体と実際の問六を抽出する。したがって、モデルに公式解答は渡らない。

## なぜ全文脈を使うか

回答に必要な数行だけを人間が選んで与えると、AIに「答えの場所」を教えることになり、本番より簡単なテストになる。Solver benchmark では、各大問の本文全体を与え、設問だけを別に抽出して本番に近い条件で評価する。

## Workers AI 実行

既定モデル:

`@cf/google/gemma-4-26b-a4b-it`

環境変数:

```bash
export CLOUDFLARE_ACCOUNT_ID='...'
export CLOUDFLARE_AUTH_TOKEN='...'
```

実行:

```bash
node benchmarks/ai-grading/run-workers-ai.mjs
```

実行時に以下を行う。

1. 公式2024年度国語問題PDFを取得
2. Cloudflare `/ai/tomarkdown` でテキスト化
3. 各大問の本文全体と問六を抽出
4. 同一問題を既定3回実行
5. 結果・利用量・字数制限チェックを `results/` にJSON保存

### 再現性テスト

既定では `seed` を指定しない。固定seedを指定した3回反復はモデルの自然な出力揺れを隠す可能性があるためである。完全な再実行確認をしたい場合だけ明示的に指定する。

```bash
BENCH_SEED=42 node benchmarks/ai-grading/run-workers-ai.mjs
```

### Thinking

Gemma 4では既定でthinkingを有効にする。無効化比較:

```bash
BENCH_THINKING=false node benchmarks/ai-grading/run-workers-ai.mjs
```

### 別モデル比較

`WORKERS_AI_MODEL` でモデルIDを変更できる。ただしモデルごとにthinking等のパラメータ仕様が異なるため、Gemma 4固有の `enable_thinking` はGemma 4にだけ送信する。別モデルでは、そのモデルの公式仕様を確認して公平な設定を別途固定する。

## 評価

自動判定するのは、字数・欄の欠落などのハード制約までとする。意味の正しさを同じAI自身に自己採点させて合否を決めない。

人間レビューでは各回答について以下を記録する。

- `correct`: 公式解答と意味が一致し、必須意味要素を満たす
- `partial`: 中心意味の一部は合うが必須要素が不足
- `incorrect`: 中心意味が異なる、または本文と矛盾
- `hallucination`: 本文にない事実を根拠として追加したか
- `missingMeaning`: 不足した意味要素
- `notes`: 判定根拠

評価テンプレートは `2024/review-template.json` を使う。

## この段階で分かること / 分からないこと

Solver benchmark で分かるのは「モデル自身が早稲渋の記述問題を正しく理解して解けるか」である。これだけでは「生徒答案に適切な部分点を付けられるか」は分からない。

Solverで十分な問題理解を確認した後に、正答・言い換え正答・部分正答・もっともらしい誤答・本文矛盾答案などを用意し、Grader benchmarkへ進む。

### 2024-2-6 の注意

この設問は、元PDFでは甲・乙を含む整理図として提示されている。PDF→テキスト変換では図の配置情報が単純化される可能性がある。したがって、2024-2-6だけ誤答した場合は、直ちにモデルの国語理解力不足とは判定せず、元の設問ページを視覚入力できる条件で再試験する。2024-1-6は純粋な文章記述なので、初期の主判定問題としてより重く扱う。

## 次の工程

1. Gemma 4 26B A4B で2024年2問を3回ずつ実行
2. 公式解答と比較して問題理解能力を人間レビュー
3. 重大な誤答がなければ採点者用rubric/test answersを作成
4. 2025・2026へ拡張
5. 開発問題と最終テスト問題を問題単位で分離
6. 最終的に2019〜2026を検証

このドラフトPRは、実推論結果と人間レビューが入るまで `main` にマージしない。
