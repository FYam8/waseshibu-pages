# 国語 AIフィードバック・ベンチマーク

目的: 早稲田渋谷シンガポール校の実際の国語過去問・公式模範解答を基準に、Workers AI が答案を一度で判定し、参考点と学習用の説明を返せるか検証する。

## 現行方針（v2）

- AI判定は答案ごとに1回とし、再判定ループや人間による答案判定を前提にしない。
- 点数は公式採点ではなく、学習上の参考値として扱う。
- 公式に詳細な部分点基準がない場合、AIが返した部分点を公式基準と表現しない。
- 内容評価と、字数・必須語・指定構文などの形式評価を分ける。
- 判定理由では、認められる内容、不足、矛盾、改善点を説明する。
- 本文全文は通常送らず、設問、公式模範解答、短く構造化した「模範解答の考え方」、形式条件、受験者答案だけを送る。

`2022-2026/grader-cases-v2.json` は、2022～2026年度から次の代表形式を1問ずつ収録する。

| 年度 | 代表形式 |
|---|---|
| 2022 | 65字以内の自由記述 |
| 2023 | 必須語・指定された書き出しと文末を伴う40字記述 |
| 2024 | 甲・乙の2欄、各10字 |
| 2025 | X・Yの2欄、指定構文、各20字、各6点 |
| 2026 | Xが10字、Yが3字の極短複数欄 |

各問には公式解答そのもの、意味または形式が一部不足する答案、中心内容が誤っている答案を置く。明確な `correct / partial / incorrect` の一致を比較するが、AIが返す参考点そのものは公式Gold点として比較しない。

現行runnerは `prompts/grader-v2.txt` と上記5年分データを既定で使う。プルリクエスト更新時は入力検証だけを行い、Workers AI推論は手動実行時だけ1モデル・1回行う。これにより意図しないAPI利用を防ぐ。

## 安全方針

- 本番アプリの問題ID・学習履歴・公開データは変更しない。
- この `benchmarks/ai-grading/` 配下だけで検証する。
- Solver テストでは公式模範解答をモデルに見せない。
- Grader テストでは、公式模範解答と問題別の短い判定観点をモデルに見せる。
- プロンプト改善に使う問題と、最終テスト問題は分離する。
- 過去問本文をこの公開リポジトリへ長文複製しない。実行時に公式PDFをCloudflare Markdown Conversionでテキスト化する。

## 2024年度 seed（v1・履歴）

### 2024-1-6
- 形式: 自由記述
- 配点: 10点
- 字数: 40字以内
- 用途: AI自由記述能力の主テスト

### 2024-2-6
- 形式: 短答記述2欄
- 配点: 甲5点 + 乙5点
- 字数: 各10字以内
- 用途: 心情変化・短答の意味判定テスト

公式資料URL・短い公式模範解答・rubric draft は `2024/questions.json` に保存する。Solver実行時は `2024/solver-cases.json` の位置情報だけを使い、公式問題PDFから本文全体と実際の問六を抽出する。したがって、モデルに公式解答は渡らない。

## 軽量 Grader ベンチマーク（v1・履歴）

実運用候補の検証では、問題を毎回解かせず、次の情報だけで生徒答案を判定する。

- 短い公式模範解答
- 人間確認済みの必須意味・意味関係・字数条件
- 実際に採点する答案

2024年度の初期セットは `2024/grader-cases.json` にある。正答、言い換え、要素不足、キーワード罠、意味が逆の答案、字数超過を含む16答案である。現在のGold labelはChatGPT Pro内で作った一次レビューであり、判断根拠は `2024/grader-pro-review.md` に記録した。本番利用前に別の人間による確認を必要とする。

`run-workers-ai-grader.mjs` は全16答案を1回のリクエストへまとめ、本文全文とGold labelをモデルへ送らない。最初は3モデルを各1回だけ比較し、最良モデルが決まってからそのモデルだけ反復して再現性を測る。これにより、3モデルを最初から各3回実行する場合より推論量を抑える。

GitHub Actionsでは `Kokugo AI grader benchmark (compact input)` を実行する。結果JSONにはモデルの判定、Gold labelとの一致数、利用量、プロンプト文字数を記録する。

## なぜ全文脈を使うか

回答に必要な数行だけを人間が選んで与えると、AIに「答えの場所」を教えることになり、本番より簡単なテストになる。Solver benchmark では、各大問の本文全体を与え、設問だけを別に抽出して本番に近い条件で評価する。

## Workers AI 実行

既定モデル:

`@cf/google/gemma-4-26b-a4b-it`

環境変数:

```bash
export CLOUDFLARE_ACCOUNT_ID='...'
export CLOUDFLARE_AUTH_TOKEN='...'
```

実行:

```bash
node benchmarks/ai-grading/run-workers-ai.mjs
```

実行時に以下を行う。

1. 公式2024年度国語問題PDFを取得
2. Cloudflare `/ai/tomarkdown` でテキスト化
3. 各大問の本文全体と問六を抽出
4. 同一問題を既定3回実行
5. 結果・利用量・字数制限チェックを `results/` にJSON保存

### 再現性テスト

既定では `seed` を指定しない。固定seedを指定した3回反復はモデルの自然な出力揺れを隠す可能性があるためである。完全な再実行確認をしたい場合だけ明示的に指定する。

```bash
BENCH_SEED=42 node benchmarks/ai-grading/run-workers-ai.mjs
```

### Thinking

Gemma 4では既定でthinkingを有効にする。無効化比較:

```bash
BENCH_THINKING=false node benchmarks/ai-grading/run-workers-ai.mjs
```

### 別モデル比較

`WORKERS_AI_MODEL` でモデルIDを変更できる。ただしモデルごとにthinking等のパラメータ仕様が異なるため、Gemma 4固有の `enable_thinking` はGemma 4にだけ送信する。別モデルでは、そのモデルの公式仕様を確認して公平な設定を別途固定する。

## 評価

プログラムが字数、必須語、欄の欠落を先に確認し、AIにはその結果も渡す。AIは意味の一致、必要な関係、矛盾、指定構文への適合を一度で判定する。

出力には次を含める。

- `referenceScore`: 公式点ではない参考点
- `verdict`: `correct / partial / incorrect`
- `partAssessments`: 複数欄の欄別判定
- `contentAssessment`: 認められる内容、不足、矛盾
- `constraintAssessment`: 形式条件への適合
- `explanation`: 判定理由
- `improvementAdvice`: 改善点
- `referenceNotice`: 参考評価であることの明示

ベンチマークでは判定ラベル、欄別ラベル、JSONスキーマを比較する。参考点の完全一致は求めない。

## この段階で分かること / 分からないこと

Solver benchmark で分かるのは「モデル自身が早稲渋の記述問題を正しく理解して解けるか」である。これだけでは「生徒答案に適切な部分点を付けられるか」は分からない。

Solverで十分な問題理解を確認した後に、正答・言い換え正答・部分正答・もっともらしい誤答・本文矛盾答案などを用意し、Grader benchmarkへ進む。

### 2024-2-6 の注意

この設問は、元PDFでは甲・乙を含む整理図として提示されている。PDF→テキスト変換では図の配置情報が単純化される可能性がある。したがって、2024-2-6だけ誤答した場合は、直ちにモデルの国語理解力不足とは判定せず、元の設問ページを視覚入力できる条件で再試験する。2024-1-6は純粋な文章記述なので、初期の主判定問題としてより重く扱う。

## 次の工程（v1当時の履歴）

1. Gemma 4 26B A4B で2024年2問を3回ずつ実行
2. 公式解答と比較して問題理解能力を人間レビュー
3. 重大な誤答がなければ採点者用rubric/test answersを作成
4. 2025・2026へ拡張
5. 開発問題と最終テスト問題を問題単位で分離
6. 最終的に2019〜2026を検証

## マージ条件

このドラフトPRは実推論結果と人間レビューが入るまで `main` にマージしない。さらに、このSolverテストの合格は本番AI採点導入の合格を意味しない。Grader benchmarkで言い換え正答・部分正答・誤答・本文矛盾答案を評価し、重大誤採点が許容範囲内であることを確認した後に、本番アプリへのAI採点導入を判断する。
